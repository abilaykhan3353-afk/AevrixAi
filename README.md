# Aevrix AI 3.0 — сборка для проверки и подключения

Обновление существующего проекта: Express, PostgreSQL и обычные HTML/CSS/JavaScript сохранены. Код разделён на модули. Исходная исправленная версия находится в `legacy/`; историческая сводка и аудит не описывают текущее поведение. Эта сборка проверена локально, но ещё не подтверждена реальными API-ключами и внешней PostgreSQL.

## Что работает в коде

- Диалоги: создание, название, поиск по названиям, архив/восстановление, удаление выбранного чата. Постраничная история, экспорт полного выбранного разговора, HTML-файл для чтения.
- Серверная история для аккаунта: клиент не задаёт контекст. Устойчивые ID, версии ответов, повтор без повторной записи вопроса, защита от повторной доставки запроса, выбор версии последнего ответа и отдельная ветка при редактировании вопроса.
- Полные сообщения вместо обрезания до 600 символов. Бюджет контекста и суммаризация целых старых обменов. Пользователь может посмотреть/удалить сводку. Явные предпочтения между чатами можно включить, выключить, изменить и удалить.
- SSE: статус этапа, текст, источники, один terminal event; partial/cancelled/failed отличаются от completed. Stop и разрыв соединения отменяют upstream. Общий deadline ограничивает цепочку API; fallback возможен только до первых токенов и только при явной настройке второй модели.
- Учебные режимы: объяснение, подсказка, проверка решения, мини-тест. Режим сохраняется в диалоге и влияет на реальный системный prompt.
- PDF/TXT/MD: проверка, ограниченное чтение PDF в worker, разбиение на фрагменты, PostgreSQL full-text retrieval, страницы/цитаты в ответе, удаление файла вместе с фрагментами. Для сканов выводится сообщение о необходимости OCR.
- Изображения: проверка бинарной сигнатуры/размера/MIME, анализ Gemini/Groq; генерация через серверный Pollinations с проверкой ответа и без ключей в публичном URL. Вложения аккаунта сохраняются в БД и защищены проверкой владельца.
- Веб-поиск: Tavily/Brave, режим Авто/Включён/Выключен. Compound снят из актуального пути. Погода с прогнозом, валютная конвертация, новости с источниками и датами. Классификатор учитывает предыдущий вопрос при продолжениях; обычный чат обходится без отдельного intent-вызова.
- Гостевые разговоры/изображения в IndexedDB; гостевые закладки и черновики отдельно от аккаунта. История прежнего приложения импортируется только по явному действию пользователя.
- Закладки аккаунта синхронизируются сервером. Голосовой ввод/озвучка, темы, эмодзи, Markdown и подсветка кода сохранены. Composer многострочный, Enter/Shift+Enter учитывают IME. Появилась кнопка к новым сообщениям при ручной прокрутке.
- Ограничения IP/пользователя, глобальная параллельность, дневной лимит генераций, строгий Origin, CSP, приватные файлы, закрытая admin без пароля, обязательный secret webhook, типы auth/report. Репорты сохраняются в БД; Telegram — опциональное уведомление с честным статусом.
- Технические метрики без текста переписки и IP: request ID, модель, результат, duration, первый текст, число HTTP-вызовов и доступный usage по провайдерам.

## Запуск

Нужен Node.js **22.22.2 или новее**; проверки выполнены на 24.20.0. Сборка использует один процесс Node и один инстанс приложения.

```powershell
npm ci --ignore-scripts
Copy-Item .env.example .env
```

Заполни `GROQ_API_KEY`. Для аккаунтов и документов также нужны `DATABASE_URL` и случайный `JWT_SECRET` минимум 32 байта. Сгенерировать секрет локально:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Пример локальной PostgreSQL: `postgresql://aevrix:password@localhost:5432/aevrix`. Для такой локальной БД укажи `PG_SSL_MODE=disable`. Для внешней БД оставь SSL с проверкой сертификатов; при необходимости укажи `PG_CA_FILE`. Параметры SSL из query string строки подключения удаляются, чтобы не отменять выбранную проверку TLS.

```powershell
npm start
```

Открыть `http://localhost:3000`. На пустой БД схема создаётся транзакционно. Без БД доступны гостевые разговоры; документы, аккаунты и серверные обращения честно недоступны. Интерфейс сообщает об отсутствии ИИ-ключа. Production-сервер не использует fixtures.

Опционально:

- `GEMINI_API_KEY` — первый провайдер анализа изображений, Groq используется резервно;
- `TAVILY_API_KEY` или `BRAVE_API_KEY` — общий поиск;
- `GNEWS_API_KEY`/`NEWSDATA_API_KEY` — новости; без них новостной запрос идёт через настроенный общий поиск;
- `POLLINATIONS_API_KEY` — генерация изображения; по умолчанию модель `flux`, доступность модели/тариф проверить отдельно;
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET` — уведомления и команды support-бота;
- `ADMIN_PASSWORD` — техническая admin-панель и просмотр сохранённых репортов.

Не добавляй `.env` в Git и не передавай ключи через интерфейс клиента. Основные model IDs, output tokens, лимиты и время ожидания задаются в `.env.example`.

## Существующая БД: backup и миграция

Старую БД не заменять пустой. Остановить запись старого приложения, сделать snapshot у провайдера или `pg_dump` в custom format. Сохранить прежний архив и настройки. Развернуть дамп в отдельную тестовую БД через `pg_restore`, проверить количество users/messages и вход со старым аккаунтом. Инструменты backup не включены в npm-проект.

Миграция **отказывает** для непустой старой таблицы `messages` без новой колонки, пока не задано `LEGACY_BACKUP_CONFIRMED=true`. Этот флаг не создаёт и не проверяет backup автоматически: он подтверждает, что владелец сделал проверенную копию. После backup и проверки на отдельной БД:

```powershell
npm run migrate
```

Миграция `db/migrations/001_v3.sql` выполняется в транзакции и отмечается в `schema_migrations`. Все прежние сообщения получают conversation ID; для каждого владельца создаётся диалог «История до обновления». Идентификаторы, содержимое, источники и даты прежних сообщений сохраняются. Старые auth cookies больше не принимаются; войти заново существующим паролем. При неудаче транзакция откатывается, сервер не принимает запросы с незавершённой схемой.

После миграции сравнить число записей и владельцев. Не запускать одновременно старый и новый сервер на одной БД. Предыдущий код не совместим с новой обязательной колонкой conversation ID.

### Откат

1. Остановить новый сервер и сохранить его БД отдельным snapshot, чтобы не потерять новые разговоры.
2. Восстановить проверенный **предмиграционный backup в отдельную БД**, не затирая обновлённую.
3. Запустить прежний архив с этой отдельной БД и прежними настройками.
4. Проверить аккаунты и количество сообщений, затем переключить размещение.

Новые сообщения из 3.0 остаются в snapshot/экспортах и требуют отдельного переноса. Автоматического разрушительного down-migration нет: сохранение данных важнее удаления новых таблиц. Без backup безопасный откат на старую схему не гарантируется.

## Размещение

Запускать **один инстанс, один процесс/worker**. In-memory rate limits, активные запросы и гостевой replay cache рассчитаны на этот режим. Для горизонтального масштабирования нужны общий limiter, распределённые блокировки, маршрутизация Stop и migration coordination. Запуск второго инстанса во время генераций может ошибочно отметить их как прерванные при startup recovery.

При размещении по HTTPS задать `NODE_ENV=production`, `PUBLIC_ORIGIN=https://your-domain.example` без завершающего `/`, и число доверенных proxy hops согласно схеме хостинга. Не ставить универсальное доверие прокси. У reverse proxy отключить буферизацию `/api/chat/stream` и установить таймаут больше `REQUEST_DEADLINE_MS` с запасом на сохранение. SQL ограничен statement/query timeout; завершающее сохранение после отмены может занять дополнительное время.

`/healthz` проверяет процесс; `/readyz` также проверяет соединение с БД. Пул и фатальные ошибки обрабатываются, процесс завершает работу после остановки активных запросов. Доверенные дополнительные browser origins задаются явно; основной клиент размещать на том же origin.

Полный журнал текста/IP отсутствует. Admin показывает технические записи последних запросов в памяти; они пропадают после перезапуска. Для постоянных метрик подключить сбор stdout. Репорты доступны администратору через `/api/admin/reports` с Basic Auth; full context прикладывается пользователем только по выбранному checkbox.

## Хранение и ограничения

- `DATA_RETENTION_DAYS=0` отключает автоматическое удаление. Положительное значение включает ежедневную очистку разговоров без новых сообщений/изменений за заданный период и старых репортов. Сообщить пользователям эту политику до включения. Вложения, версии и фрагменты удаляются через FK cascade вместе с разговором. При ручном удалении выбранного разговора данные удаляются окончательно.
- Вложения аккаунта: суммарно 60 МБ. Изображение до 6 МБ; документ до 5 МБ/150 страниц/400000 символов/400 фрагментов. Проверка изображений по сигнатуре не заменяет полноценный антивирусный скан.
- Гостевое хранилище: до 12 МБ сериализованных данных; браузер может ограничить квоту или удалить данные. Ошибка сохранения показывается, текст не заявляется сохранённым.
- RAG сейчас **лексический PostgreSQL поиск**, без embeddings, reranker и OCR. Ответ получает только найденные фрагменты. При отсутствии совпадений бот честно предлагает уточнить запрос; это не доказательство отсутствия информации в файле.
- Token budget рассчитан через `o200k_base` с запасом 15%; это оценка для разных моделей. При переполнении текст не обрезается, запрос отклоняется с понятным сообщением. Не более 2000 несуммированных сообщений в одном построении контекста. Сводки могут быть неточны; полная история остаётся доступной.
- Версию ответа можно переключить у последнего вопроса; более ранние изменения создают ветку. Отдельных workspace-проектов/папок пока нет.
- Share — скачиваемый HTML-файл для чтения, без публичной серверной ссылки, отзыва и срока действия. Вложения не встраиваются в экспорт. Поиск в сообщениях фильтрует только загруженные страницы; это обозначено в UI.
- Web Speech API зависит от браузера и его службы распознавания. Полноценного двустороннего голосового диалога, scheduler, платежей, выполнения кода или Telegram-чатов с общей историей нет.
- Клиент сохраняет несентные черновики локально по аккаунту/диалогу; ответы аккаунта в гостевое хранилище не пишутся. Старое загрязнённое localStorage не удаляется автоматически и не импортируется без действия пользователя.

## Проверки

```powershell
npm test
npm run test:browser
npm run eval
```

Node-тесты используют настоящий Express и **PGlite — PostgreSQL в WebAssembly**, а также fixtures только для внешних сервисов. Проверяют SQL/миграцию, транзакции, ownership, перегенерацию, cancellation/deadline, ошибки сохранения, вложения/фрагменты, SSE, XSS и маршрутизацию инструментов. Это не тест внешнего TCP/TLS-сервера PostgreSQL.

Браузерный скрипт запускает изолированный **Chrome headless**, не использует профиль пользователя. Нужен установленный Chrome; альтернативный Chromium channel задаётся `TEST_BROWSER_CHANNEL`. Screenshot и JSON-results сохраняются в `test-results/` или каталоге аргумента. Подтверждены ширины 360/390/768/1440 px. Реальный iOS и экранная клавиатура отдельно не проверены. В данной sandbox скачивание Blob-файла отменялось браузером: проверено содержимое JSON Blob, а фактическое сохранение браузером остаётся непроверенным.

```powershell
npm run preview
```

Это отдельный тестовый сервер `http://127.0.0.1:3033` с **явно тестовыми ответами и БД в памяти**. Он запрещён при NODE_ENV=production и предназначен только для просмотра/проверок. Не использовать для размещения настоящего бота.

`npm run eval` измеряет локальную обработку fixture-запросов; эти p50/p95 не характеризуют скорость/качество реальных ИИ. Для live-проверки ключей предусмотрен `npm run check:models` (metadata GET, без генерации); он ещё не выполнялся с настоящими ключами. Затем отдельно проверить текст, vision, источники, образец документа и генерацию изображения с согласованным бюджетом.

## Сборка статических зависимостей

Vendor-файлы включены в архив, закреплены lockfile, обслуживаются локально. Для воспроизводимого обновления:

```powershell
npm ci --ignore-scripts
npm run build
```

Licenses DOMPurify, marked и highlight.js находятся в `public/vendor/`. Код исторической версии в `legacy/` не обслуживается по HTTP и не импортируется рабочим сервером.
