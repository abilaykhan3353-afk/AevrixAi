# Aevrix Ai — сводка проекта (для продолжения в новом чате)

Учебный веб-чат-бот, сделанный с нуля в рамках вайб-кодинга. Автор — новичок,
учится программировать самостоятельно. Ниже — всё важное, чтобы новый чат
Claude мог продолжить работу без повторного объяснения истории.

## ОБНОВЛЕНИЕ: добавлены аккаунты, БД и стриминг (см. раздел ниже)

В проект добавлены три новые системы: потоковые ответы (текст печатается
постепенно), аккаунты пользователей (регистрация/вход) и база данных
PostgreSQL для хранения истории переписки авторизованных пользователей.
Подробности — в разделе "Аккаунты, БД и стриминг (новое)" ниже. Код НЕ
запускался и НЕ тестировался живьём (в песочнице, где это писалось, нет
доступа к сети для npm install) — синтаксис всех файлов проверен
(`node --check`), но перед деплоем нужно проверить работу локально
(`npm install && node server.js`) и завести настоящую БД.

## Стек и архитектура

- **Frontend**: чистые HTML/CSS/JS, без фреймворков (`index.html`, `style.css`, `script.js`)
- **Backend**: Node.js + Express (`server.js`), запускается командой `node server.js`
- **ИИ-провайдер**: Groq API (бесплатный, ключ `GROQ_API_KEY`)
  - Обычное общение → модель `openai/gpt-oss-20b` (без поиска, большой лимит)
  - Вопросы, требующие свежих данных → `groq/compound` (умеет искать в интернете),
    с автопереключением на `groq/compound-mini` при тайм-ауте
  - Определение "нужен ли поиск" — эвристика по ключевым словам (функция
    `needsSearch()` в server.js: "сегодня", "новости", "погода", год 2024+ и т.д.)
- **Анализ фото**: сначала пробуем **Gemini** (`GEMINI_API_KEY`, модель
  `gemini-3.7-flash`) — стабильнее для картинок; если недоступен — резерв
  через Groq `qwen/qwen3.6-27b` (у Groq модели для фото часто снимаются с
  доступа, это уже случалось дважды за проект)
- **Резервный поиск**: Tavily (`TAVILY_API_KEY`), подключается автоматически,
  только если Groq полностью недоступен (лимит/ошибка/тайм-аут)
- **Локальная "болталка"**: мгновенные ответы без обращения к ИИ на короткие
  фразы (до 25 символов) — приветствия, шутки, "как дела" и т.п. Список в
  массиве `localReplies` в script.js. Важно: matching идёт по ЦЕЛЫМ словам
  (через `matchesWholeWord`), а не подстрокой — раньше был баг, когда "да"
  ложно совпадало внутри слова "погода".

## Дизайн

Финальная версия — стиль "стеклянного" (glassmorphism) AI-продукта:
тёмный/светлый переключаемые темы, мягкие цветные пятна на фоне ("аврора"),
экран приветствия с логотипом, SVG-иконки вместо эмодзи в интерфейсе (кроме
самого пикера эмодзи для вставки в сообщения — там эмодзи уместны).

Полностью адаптирован под мобильные устройства:
- боковая панель становится горизонтальной полосой сверху на телефоне
- используется `visualViewport` API для точной высоты (проблема с клавиатурой
  на iOS)
- `min-width: 0` добавлен во всех критичных местах flexbox-вёрстки
  (частый источник багов "сжатия" элементов)
- кнопка эмодзи скрыта на мобильном (есть системная эмодзи-клавиатура)
- safe-area отступы для вырезов/чёлки

## Функции бота

- Тема оформления (светлая/тёмная), сохраняется в localStorage
- Память о разговоре (история отправляется вместе с каждым запросом,
  ограничена 10 последними сообщениями по 600 символов каждое — иначе Groq
  выдаёт ошибку 413 "request too large")
- Сохранение переписки между перезагрузками страницы (localStorage)
- Поиск по истории чата с подсветкой совпадений
- Копирование сообщений, озвучка ответов (Web Speech API), голосовой ввод
- Загрузка и анализ фото
- Настройки: имя бота, показ времени сообщений, озвучка, **стиль общения**
  (обычный / с юмором / дерзко с матом / официально — меняет системный
  промпт на сервере, параметр `tone` передаётся с фронтенда)
- Очистка истории чата
- **Админ-панель** `/admin` — показывает всю переписку всех пользователей
  (логируется в `conversations.log.jsonl` на сервере), защищена паролем
  через `ADMIN_PASSWORD` (HTTP Basic Auth). Если пароль не задан — страница
  открыта всем, кто знает ссылку — это осознанный риск, о котором
  пользователь предупреждён.

## Уже исправленные баги (чтобы не наступить на те же грабли)

1. `[hidden]` атрибут перебивался `display:flex` в CSS → добавлено
   глобальное правило `[hidden] { display: none !important; }`
2. Flexbox-контейнеры не сжимались правильно (`.chat-panel`, `.chat-messages`,
   `.input-pill`, `#userInput`, `.header-identity`) → добавлен `min-width: 0`
   / `min-height: 0` везде, где нужно
3. Локальная "болталка" перехватывала длинные сообщения с приветствием в
   начале ("привет какая погода...") → добавлено ограничение: локальные
   ответы только для сообщений короче 25 символов
4. Короткие ключевые слова "да"/"нет" ложно совпадали внутри других слов
   → переход на поиск по целым словам через regex с границами
5. Кнопка эмодзи не открывалась (клик по SVG-иконке внутри кнопки считался
   "кликом снаружи" и document-обработчик тут же закрывал панель) →
   добавлен `e.stopPropagation()`
6. История разговора могла разрастись и вызвать 413 у Groq → ограничена по
   длине и количеству + сервер автоматически повторяет запрос без истории
   при 413
7. Сервер мог "упасть" целиком при необработанной ошибке → добавлены
   `process.on('uncaughtException'/'unhandledRejection')`, сервер продолжает
   работать и просто логирует ошибку
8. Groq тайм-ауты на сложных вопросах → двухступенчатая попытка (сначала
   мощная модель 20с, потом облегчённая ещё 20с) + понятное сообщение об
   ошибке вместо зависания

## Аккаунты, БД и стриминг (новое)

### Новые файлы
- `db.js` — подключение к PostgreSQL (через переменную `DATABASE_URL`) и
  создание таблиц `users` и `messages` при старте сервера
- `auth.js` — регистрация/вход/выход (bcryptjs для хеширования паролей,
  JWT в httpOnly-cookie для сессии), middleware `authOptional`/`authRequired`
- `history.js` — сохранение и чтение истории сообщений из БД для
  авторизованных пользователей

### Почему PostgreSQL, а не SQLite
Бесплатный Render **не хранит файлы на диске** между деплоями и
перезапусками — SQLite-файл стирался бы, и все аккаунты/история исчезали
бы. Поэтому нужна внешняя БД. Рекомендован **Neon** (https://neon.tech,
бесплатный tier, PostgreSQL) — просто скопировать connection string в
`DATABASE_URL`. Альтернативы: Supabase, платный Render Postgres.

### Новые переменные окружения (см. `.env.example`)
```
DATABASE_URL=...   # обязателен для аккаунтов, строка подключения к Postgres
JWT_SECRET=...     # обязателен для аккаунтов, случайная строка 32+ символов
```
Без них сервер продолжает работать как чат-бот без аккаунтов (эндпоинты
`/api/auth/*` и `/api/history` вернут понятную ошибку 503).

### Новые эндпоинты на сервере
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`
- `GET /api/history` / `DELETE /api/history` — только для авторизованных
- `POST /api/chat/stream` — **заменил** старый `POST /api/chat`. Отдаёт
  ответ через Server-Sent Events (`data: {...}\n\n`): `{delta}` — кусочек
  текста, `{done, sources, usedSearch}` — конец, `{error}` — ошибка.
  Настоящий стриминг работает только для обычной модели без поиска
  (`openai/gpt-oss-20b`); поисковые модели Groq (`groq/compound*`),
  анализ фото и резервный Tavily-поиск шлют весь текст одним `delta`
  (технически не потоково, но по тому же протоколу — фронтенду не нужно
  различать эти случаи).

### Фронтенд
- `script.js`: `streamAskServer()` читает SSE-поток через
  `fetch().body.getReader()`, `sendMessage()` переписан на стриминг,
  создаёт пустой пузырь и дописывает в него текст по мере прихода
  кусочков (без разбора markdown на каждый чанк — это делается один раз
  в конце, когда весь ответ получен)
- Кнопки "копировать"/"озвучить" у сообщений теперь читают
  `messageDiv.dataset.rawText` в момент клика, а не текст из замыкания —
  иначе для стримингового сообщения они копировали бы пустую строку
- Если пользователь авторизован — история подгружается через
  `GET /api/history` вместо localStorage; если гость — всё работает как
  раньше (localStorage)
- Добавлена кнопка аккаунта в шапке (`accountBtn`) и модалка
  вход/регистрация/аккаунт (`authOverlay` в `index.html`, стили в
  `style.css` в разделе "Аккаунт: вкладки и форма входа/регистрации")

### Что ещё стоит сделать / проверить
1. Установить зависимости (`pg`, `jsonwebtoken`, `bcryptjs`, `cookie-parser`
   добавлены в `package.json`, но `npm install` ещё не запускался)
2. Завести бесплатную БД на Neon, вставить `DATABASE_URL` и `JWT_SECRET` в `.env`
3. Запустить локально (`node server.js`) и вручную проверить: обычный чат
   со стримингом, регистрацию, вход, что история сохраняется и
   восстанавливается после перезагрузки страницы под своим аккаунтом
4. На Render — добавить `DATABASE_URL` и `JWT_SECRET` в Environment Variables
5. Источники (🔎) сейчас не показываются для потокового ответа обычной
   модели (у неё их и не бывает — источники только у поисковых моделей,
   которые не стримятся), так что это не баг, а особенность архитектуры
6. Множественные диалоги (как в ChatGPT) — таблица `messages` уже привязана
   к `user_id`, так что при желании можно добавить таблицу `conversations`
   и поле `conversation_id`, но сейчас у каждого пользователя одна
   сплошная история, как было раньше в localStorage

## Деплой (в процессе, ещё не завершён)

- Репозиторий на GitHub: `github.com/abilaykhan3353-afk/aevrix-ai`
- Хостинг: **Render.com**, бесплатный тариф (засыпает после 15 мин простоя,
  первый запрос после этого — 30-50 секунд)
- Регион выбран: **Singapore** (ближе всего к Казахстану из доступных:
  Oregon/Ohio/Virginia/Frankfurt/Singapore)
- **ТЕКУЩАЯ ПРОБЛЕМА**: при загрузке на GitHub пользователь перетащил саму
  папку проекта (а не файлы по отдельности), из-за чего все файлы оказались
  во вложенной подпапке репозитория вместо корня. Render ищет
  `package.json` в корне → ошибка `ENOENT`. Решение в процессе: указать в
  настройках Render (Settings → Build & Deploy → Root Directory) точное имя
  этой подпапки и запустить Manual Deploy → Deploy latest commit. Ожидаем
  результат от пользователя.
- Build Command: `npm install`
- Start Command: `node server.js`
- Ключи вводятся в Render через Environment Variables (не через .env файл)
