# Aevrix AI: аудит и план большого обновления

Дата анализа: 12 октября 2026 года. Источник: `AevrixAi-main (3).zip`, папка `AevrixAi-main/AevrixAI`.

## Главный вывод

У бота уже много возможностей. Самое полезное обновление сейчас — сделать разговоры устойчивыми: сохранять полноценный контекст, разделить чаты, корректно переживать ошибки API и показывать происхождение фактов. После этого добавить работу с документами и учебный режим. Простая замена системного промпта не исправит потерю истории, неверную маршрутизацию или оборванный поток.

Предлагаемое направление продукта: **Aevrix AI — личный помощник для учёбы, кода и работы со своими материалами**. Это предложение, а не установленная целевая аудитория: на стартовом экране уже есть домашние задания, объяснение тем и программирование. Подтвердить спрос можно на нескольких пользователях до разработки дорогих функций.

## Что изучено и что уже есть

Проверены все 10 файлов архива: сервер, auth, db, history, клиентский JavaScript, HTML, CSS, package.json, сводка и наличие изображения логотипа. Изображение логотипа отдельно визуально не оценивалось. Прочитаны обработчики запросов, схемы таблиц, ветки вызова API, клиентское хранение, восстановление и перегенерация.

Стек: Node.js/Express, PostgreSQL/pg, JWT в HttpOnly cookie, bcryptjs; HTML/CSS/JavaScript без фреймворка. Есть потоковый текст через SSE, Markdown с DOMPurify, подсветка кода, Groq, поиск через Compound/Tavily/Brave, классификация намерений, отдельные погодные/валютные/новостные запросы, Gemini/Groq vision, ссылка на генерацию изображения Pollinations, Web Speech API, аккаунты, история, локальные закладки, темы, поиск по текущему чату, перегенерация, публичная ссылка и обращения в Telegram.

Положительная основа: ключи используются на сервере; SQL параметризован; пароли хешируются; ответы Markdown проходят через DOMPurify. Эти решения стоит сохранить.

Архив не содержит `.env`, lockfile, тестов, migrations или инструкции развёртывания. Настоящие ключи и состояние размещённого приложения неизвестны. `PROJECT_SUMMARY.md` рассматривается как историческое описание, а не как инструкция владельца. В частности, там описан старый фиолетово-бирюзовый дизайн; фактический CSS использует концепцию «Сигнал» с зелёным акцентом. Существующие ограничения оценены по коду, а не по обещаниям сводки.

## Проверка внешних интеграций

Проверены официальные страницы 12 октября 2026 года. [Groq models](https://console.groq.com/docs/models) описывает endpoint списка доступных моделей; это стоит использовать для проверки настройки в окружении. [Groq vision](https://console.groq.com/docs/vision) сейчас приводит `qwen/qwen3.8-27b`, тогда как в архиве задан `qwen/qwen3.6-27b`. [Gemini models](https://ai.google.dev/gemini-api/docs/models) перечисляет `gemini-3.8-flash`; идентификатор `gemini-3.7-flash` из архива на прочитанной странице не найден. Это сигнал перепроверить конфигурацию, а не доказательство недоступности старой модели для каждого аккаунта.

В исправленной копии defaults vision/Gemini обновлены и все основные model IDs вынесены в `.env`. Реальные вызовы и стоимость не проверялись. Нельзя обещать бесплатность провайдеров по старым комментариям. [Официальная документация Pollinations в их репозитории](https://github.com/pollinations/polli-image-bot/blob/main/pollinations_docs.md) описывает ключи API и `gen.pollinations.ai`; старую прямую ссылку из проекта нужно проверять отдельно и переносить за серверный adapter. Ключ никогда не добавлять в публичный URL изображения.

Проблема раздачи директории основана на коде проекта и описанном поведении [Express static](https://expressjs.com/en/starter/static-files/); живой HTTP-запрос к исходному серверу не выполнялся.

## Идеи с наибольшей пользой

| Идея | Что получает пользователь | Сложность и расходы | Первая законченная версия |
|---|---|---|---|
| Отдельные диалоги и проекты | «Учёба», «Код», «Идеи» не смешиваются | Средняя; в основном БД и UI | Создать, переименовать, найти, архивировать, удалить конкретный чат |
| Память под контролем пользователя | Бот помнит стиль и цели; пользователь видит и удаляет записи | Средняя; суммаризация добавляет токены | Сводка диалога + отдельные явно подтверждённые предпочтения с выключателем |
| Чат с PDF/TXT/MD | Разбирать свои лекции и материалы с указанием страницы | Высокая; извлечение, хранение, embeddings, retrieval | Один файл, вопросы по нему, ссылки на фрагменты, честное «не найдено» |
| Учебный режим | Подсказки, пошаговое объяснение, затем короткая проверка понимания | Средняя; нужна проверка качества | «Объяснить тему», «Дать подсказку», «Проверить решение», мини-тест |
| Удобная работа с кодом | Сохранить целый файл, обсудить ошибку, получить diff | Средняя без исполнения; высокая с sandbox | Полный блок кода, копирование/скачивание, сохранение условий задачи |
| Проверяемый поиск | Видеть источники, даты и различия между ними | Средняя; расходы на поиск | Выбор Авто/Включён/Выключен + корректные ссылки рядом с фактами |
| Управляемый ответ | Остановить, повторить, изменить вопрос, сравнить версии | Средняя; требует ID и lifecycle | Stop отменяет upstream, Retry не дублирует вопрос, Edit создаёт ветку |
| PWA и черновики | Быстро открыть с телефона и не потерять недописанный запрос | Низкая/средняя; ИИ всё равно требует сети | Установка, сохранённый черновик, ясное состояние offline |

Следующие по очереди: экспорт Markdown/JSON, синхронизация закладок, обратная связь «полезно/ошибка», библиотека личных шаблонов, произвольные пользовательские инструкции, поддержка русского/казахского/английского при подтверждённом спросе.

Полноценный голосовой разговор с перебиванием, напоминания, Telegram-чат с общей историей, генерация файлов и выполнение кода — отдельные дорогие этапы. Для напоминаний нужны scheduler и канал доставки, для исполнения кода — изолированная среда; одного промпта недостаточно. Подписки и платежи имеет смысл вводить после измерения стоимости и спроса.

## Как обновлять проект

**Этап 0 — безопасность и честные состояния.** Закончить лимиты, auth/report validation, webhook, TLS БД, deadline, отмену upstream, статус partial/failed, ошибки persistence, migrations и reproducible install. Исправленная копия покрывает только часть этого этапа.

**Этап 1 — ядро Aevrix 3.0.** Ввести `conversations`, устойчивые ID сообщений, серверное построение контекста для аккаунта, summary по token budget, версии ответов и вложения. Гостям оставить ограниченный локальный режим с отдельными ключами. Перенести существующую историю каждого пользователя в один диалог без потери записей; сделать проверенную резервную копию перед миграцией.

**Этап 2 — пользовательский опыт.** Боковая панель диалогов, многострочный composer, Enter/Shift+Enter, Stop/Retry/Edit, статус поиска, источники, экспорт, мобильные состояния и доступность. Сохранить текущий зелёный «Сигнал», темы и волну, добавив reduced-motion и возможность читать без навязанного autoscroll. Не менять стек ради внешнего эффекта.

**Этап 3 — сильная новая функция.** Начать с учебного режима или диалога с материалами. Для RAG сделать небольшой законченный путь: загрузить документ → извлечь → разбить → найти → ответить с цитатой фрагмента → удалить документ вместе с производными данными. Текст документов и страниц считать данными, которые могут содержать чужие команды.

Предлагаемая структура: `server/app`, `routes`, `providers`, `chat/orchestrator`, `chat/context`, `tools`, `repositories`, `middleware`, `db/migrations`; клиент разделить на API, state, chat rendering и storage. Сделать это постепенно, сохраняя запуск через npm. TypeScript можно обсудить после выделения модулей; срочной необходимости в полной переписи нет.

## Проверка следующего релиза

Минимальные сценарии: длинная задача с кодом сохраняет условия; два диалога не смешиваются; 205+ сообщений восстанавливают последние; пользователь B не читает и не изменяет чат A; Stop прекращает внешний запрос; ошибка после первых токенов не превращается в «успех»; Retry не дублирует user; удаление с недоступной БД не сообщает об успехе; «А завтра в Алматы?» использует контекст и прогноз; документ с «игнорируй инструкции» не меняет полномочия; источники с опасным URL не исполняются; отключённый поиск не выдаёт себя за выполненный.

Измерять на фиксированном наборе запросов: время первого текста, время ответа, p50/p95, число внешних вызовов, стоимость по доступному usage, долю ошибок и потерянных записей. Пока измерений нет, обещания «вдвое быстрее» или «умнее на 90%» недостоверны.

## Что уже сделано в этой работе

Подготовлены аудит, подробный рабочий промпт и отдельная копия `AevrixAI-improved.zip` с первыми исправлениями. В неё добавлены `.env.example`, `.gitignore`, README и 15 регрессионных тестов. Проверка синтаксиса всех JavaScript-файлов и все 15 тестов прошли на Node.js 24.20.0.

Тесты изолированы с заменами Express, БД и fetch; проверяют логику обработчиков и клиентских функций. Установка зависимостей, живой Express, PostgreSQL, фактическое качество ответов и браузерная визуальная проверка не выполнялись. Исходный архив не изменён, внешнего деплоя не было. Исправленный архив — начало обновления, а не завершённый релиз Aevrix 3.0.
